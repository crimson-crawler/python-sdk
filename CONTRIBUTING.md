# Contributing

Thank you for helping improve Crimson Crawler. Use the repository issue tracker for reproducible defects, documentation gaps, and focused feature proposals.

## Security reports

Do not open a public issue for a suspected vulnerability or exposed credential. Follow [SECURITY.md](SECURITY.md) and use GitHub's private vulnerability reporting channel.

## How changes land

This repository is a published export of Crimson Crawler's source of truth, not the place the code is written. Forking is disabled and pull requests are not accepted. Each release replaces the tree wholesale, so a merged patch would be overwritten by the next release. Maintainers close pull requests without merging them. Changes are made upstream and shipped through the release process.

The issue tracker is the contribution path, and a good issue does most of the work of a patch:

1. State the observed behavior, the expected behavior, and the relevant package, release, documentation, or server version.
2. Include the smallest reproduction you can: a request, command, configuration, or short snippet.
3. For a proposal, describe the use case before the API you have in mind.
4. Call out any security or compatibility impact.

Release workflows, package versions, and exported artifacts are maintained by the Crimson Crawler release process.

By contributing, including code, configuration, or logs pasted into an issue, you confirm that you have the right to submit the work under this repository's Apache License 2.0 and that no employer, customer, partner, or other agreement prevents its publication.

Keep discussion technical and respectful. Harassment, personal attacks, disclosure of private information, and unauthorized security testing are not acceptable. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Support

Use the repository issue tracker for defects and the [Crimson Crawler documentation](https://crimsoncrawler.com/docs/introduction/) for setup and usage. Security reports must use the private process above.
